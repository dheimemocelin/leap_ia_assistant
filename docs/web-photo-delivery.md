# Correção de fotos e continuidade do chat

Problemas reproduzidos: chat de teste não carregava a biblioteca real; interface só mostrava IDs; modo de catálogo pendente produzia recusas; seleção BEV/REEV perdia a pergunta original para consultar fatos. No ensaio real, a legenda gerada pelo LLM também inventou URLs example.com apesar da entrega real funcionar.

Correções: snapshot das 12 fotos e três identidades aprovado após autorização explícita do usuário (4 B10 BEV, 4 B10 REEV, 4 C10 BEV). Aprovação restrita ao teste protegido, registrada em data/validation/media-chat/approval.json. Os bytes e hashes foram preservados, sem nova cópia/download; catálogo original data/catalog permanece pending_review. Browser usa o snapshot autorizado e entra diretamente no modo de teste. CLI --reviewed-catalog também utiliza essas fotos autorizadas no teste local.

A resposta contém somente media_ids, e /web/media/resolve resolve os IDs já concedidos à sessão para tokens aleatórios. /web/media/{token} requer a mesma sessão, confere veículo/mídia aprovados, direitos, existência/confinamento, hash e assinatura JPEG; devolve bytes image/jpeg com no-store. Não aceita URL/caminho do cliente nem envia base64 ao LLM. JS cria elementos img de mesma origem (clicáveis para ampliar), sem interpretar Markdown ou HTML do modelo.

Fotos e saudação passam a ter resposta determinística: o LLM não redige legenda nem inventa link; fotos custam zero chamadas LLM. Fontes de imagens usam identificadores derivados do hash da imagem. O pedido original é preservado durante esclarecimento de motorização (incluindo “a elétrica”), mas uma pergunta técnica depois de fotos não herda a intenção de imagem indevidamente. Tópicos específicos sem fatos, como capacidade da bateria, não são respondidos com especificações sem relação.

Ampliação estreita dos fatos internos: B10 BEV potência 218 cv e porta-malas traseiro 405 L, conferidos no conteúdo indexado oficial de https://www.leapmotor.com.br/b10.html (a abertura direta da página expirou; essa limitação consta no review.json). Não foram importados valores financeiros nem estoque. C10 BEV mantém autonomia 338 km PBEV. Isso ainda não é um catálogo completo e não habilita alegações livres sobre campos ausentes.

Evidência real pelo túnel: login HTTPS 200; pergunta de fotos B10 BEV retornou três media_ids; três GETs de imagens autenticados retornaram JPEG 200 e hashes originais. Outro ensaio real “Quero conhecer o B10” → “BEV” retornou as frases revisadas de 218 cv e 405 L; “Me mostra por dentro” retornou dois IDs internos B10 BEV e os dois arquivos JPEG 200. Esse ensaio ainda usava o LLM para legenda e revelou as URLs inventadas; a correção posterior foi testada deterministicamente, sem inferência adicional, para impedir essa classe de erro. Nenhuma chave ou cookie foi registrado.

Validação final: 106 testes passaram; Ruff, node --check, compileall e git diff --check passaram. Novas coberturas: entrega autenticada, grants por sessão, isolamento, mídia não solicitada, revogação, arquivo ausente/corrompido, MIME, snapshot autorizado versus original pendente, fotos dos três veículos, continuidade por motorização, categoria interior, pergunta técnica após fotos, saudação e ausência de LLM/URLs fabricadas na resposta de foto. Fixture JPEG mínima nos testes de transporte não representa foto comercial; testes de hash dos arquivos reais foram separados.

Limites: aprovação é para o teste local protegido, não redistribuição via CRM/WhatsApp. A biblioteca de fatos continua limitada e depende de revisão/atualização. Autenticação/sessões são em memória, URLs são privadas por sessão e não links públicos permanentes. Aplicar alterações reinicia sessões do navegador; entrar novamente com a mesma senha. CommercialPolicyEngine, barreira HTTP e .env não foram modificados por esta correção.
