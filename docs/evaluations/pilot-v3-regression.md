# Pilot v3: greeting and missing evidence selection

Observed in the WhatsApp pilot after abf9339: returning `Oi` produced an unrelated generic reply; `Saber sobre o b10` produced a failed-query fallback.

Sanitized inbox telemetry showed `other/question_shape` and `technical/missing_required_evidence` respectively. No raw conversation, contact or provider payload was logged for this diagnosis.

Root causes in `SalesAgent.consult` and `compose_conversation`:
- Returning greetings with an existing vehicle were interpreted as unknown messages before the greeting guard.
- Successful approved evidence retrieval was discarded when a wording draft omitted fact IDs.

Two deterministic regression tests initially failed (wrong intent; missing source_ids). They now pass. Greeting bypasses unknown-intent interpretation; required facts are attached from the revalidated server-side query evidence when the draft omits IDs. Explicit invalid IDs, revoked facts, unsafe prose and commercial policy checks remain enforced. The composition contract now makes the required-facts flag explicit and tells the provider to place optional questions only in the structured field.

Validation: 307 Pytest tests passed; Ruff, Python compilation and git diff --check passed. One existing upstream LangChain deprecation warning remains. No real provider call or outbound WhatsApp message was generated by these tests. A complete semantic and naturalness evaluation with the real model remains pending; these two regressions do not prove overall conversation quality. No commercial policy or consent rule changed.
